NetCut QA Manual

วิธีเทสต์เน็ตหลุดของ vdoc (video-call-app, online-self, video-call-agent) บนเครื่องจริง · agent ใช้ Chrome บน MacBook · ลูกค้าใช้มือถือ Android ต่อสาย USB

1. ติดตั้งครั้งแรก

  1. ติดตั้ง Docker Desktop (โหลดจาก docker.com หรือ brew install --cask docker) แล้วเปิดครั้งแรกให้เสร็จ
  2. ติดตั้ง Node และ adb: 
    brew install node
brew install --cask android-platform-tools
  3. มือถือ: เปิด Developer options → USB debugging แล้วเสียบสาย USB กับ Mac กดยอมรับบนมือถือ (netcut สั่งมือถือผ่านสายนี้)
  4. ถ้ามือถือถามให้อนุญาต USB debugging จาก Mac เครื่องนี้ ให้ติ๊ก "Always allow" แล้วกด Allow

2. เริ่มทุกครั้ง

  1. เปิด Docker Desktop (ถ้ายังไม่เปิด npm start จะเปิดให้)
  2. ครั้งแรกเท่านั้น: git clone git@github.com:thyahan/netcut.git
  3. cd netcut แล้ว npm start (ครั้งแรกใช้เวลาสักพัก เพราะโหลด AdGuard)
  4. ถ้า macOS ถามว่าให้ node รับการเชื่อมต่อ ให้กด Allow
  5. หน้าเว็บ netcut จะเปิดขึ้นมาเอง (ถ้าไม่ขึ้น เปิด http://127.0.0.1:8790) · ปล่อยหน้าต่าง terminal ไว้ อย่าปิด
  6. มุมขวาบนต้องมีจุดเขียว 3 จุด: มือถือต่อ USB, AdGuard, DNS relay
  7. IP ของ Mac อยู่ในกล่อง "บล็อก Vroom" ตรง "ตั้ง DNS มือถือเป็น" ใช้กับ 2 เคสบล็อก Vroom
ห้ามใช้ adb แบบ wireless และห้ามต่อ VPN ตอนเทสต์ · staging เปิดคิว 10:00–20:00

3. ปุ่ม

ปุ่มทำอะไรคำสั่งจริง

4. เคสที่เทสต์

เคสที่ไม่ได้เขียนเรื่อง DNS ให้ใช้ DNS ปกติ (DHCP) ทั้งสองเครื่อง

ทุกเคสที่กด 1 เลือก "วิธีตัดเน็ต" ได้ 2 แบบ ทำซ้ำอีกรอบด้วยอีกแบบได้:

  • หลุดจากเครือข่าย (ค่าเริ่มต้น) เหมือนเดินออกนอกระยะ Wi-Fi มือถือรู้ตัวทันที
  • Wi-Fi ยังต่อ แต่แอปใช้เน็ตไม่ได้ เลือกแอป Chrome (online-self) หรือ vdoc app เหมือนเน็ตบ้านล่มทั้งที่ Wi-Fi ยังเต็ม แอปอาจรู้ตัวช้ากว่า เพราะต้องรอ timeout · ผลของแบบนี้ยังไม่เคยเทสต์ ให้จดสิ่งที่เห็นไว้

5. ตั้ง DNS (เฉพาะ 2 เคสบล็อก Vroom)

มือถือ Android

  1. Settings → Wi-Fi → กดค้างหรือกด ⚙️ ที่เครือข่ายที่ต่ออยู่ → Advanced / View more
  2. IP settings → Static (IP, Gateway, Prefix มักกรอกให้แล้ว ถ้าว่างให้ใส่ IP ปัจจุบันของมือถือ, Gateway ของ router, Prefix 24)
  3. DNS 1 = IP ของ Mac · DNS 2 = ลบให้ว่าง → Save
  4. เช็คบนหน้าเว็บ กล่อง "บล็อก Vroom": แถวมือถือต้องขึ้น DNS เป็น IP ของ Mac และขึ้นว่า "จะโดนถ้าบล็อก"
  5. คืนค่า: IP settings → DHCP → Save

MacBook

  1. กดปุ่ม ให้ Mac โดนบล็อกด้วย ในกล่อง "บล็อก Vroom" แล้วใส่รหัสผ่านของ Mac
  2. เช็ค: แถว MacBook ขึ้นว่า "จะโดนถ้าบล็อก"
  3. คืนค่า: กดปุ่ม คืน DNS ของ Mac แล้วใส่รหัสผ่าน
ทำไม่ได้: บล็อก Firebase อย่างเดียว (Firebase ต่อค้างไว้ตั้งแต่เปิดแอป การบล็อก DNS ตัดของที่ต่ออยู่แล้วไม่ได้) · Mac แบบ Wi-Fi ต่ออยู่แต่ไม่มีอินเทอร์เน็ต netcut ทำให้ไม่ได้ ให้จำลองใน Chrome ของ agent: DevTools → Network → Offline (ภาพและเสียงวิดีโอคอลยังไหลต่อ)
ระวัง: ตอนมือถือใช้ DNS ของ Mac ห้ามตัดเน็ต Mac (ปุ่ม 3 จะถูกกันไว้) และห้ามปิด netcut ไม่งั้นมือถือเปิดเว็บไม่ได้ คืน DNS ก่อนทุกครั้ง

6. จบการเทสต์

  1. คืน DNS มือถือเป็น DHCP และกด คืน DNS ของ Mac (ถ้าตั้งไว้) · ทั้งสองแถวในกล่อง "บล็อก Vroom" ต้องขึ้น "ไม่โดน"
  2. กด คืนทุกอย่าง
  3. กลับไปที่ terminal ที่รัน npm start แล้วกด Ctrl-C
  4. npm run stop ปิด AdGuard (Docker Desktop ปิดทิ้งได้ถ้าไม่ใช้แล้ว)
